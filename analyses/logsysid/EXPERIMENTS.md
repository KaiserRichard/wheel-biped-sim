# P3 experiments: bench first, robot second

Prepared 2026-11-17. This is a proposed procedure, not a record of hardware tests. All numeric excitations below are rehearsal settings; the robot owner must set the permitted torque, speed, travel, current, voltage and temperature limits from the actual hardware before enabling a drive. Historical references were read but are not bundled; see `SOURCE_MANIFEST.json` for opaque lineage hashes. All settings require independent hardware confirmation.

## Before the visit

Confirm the board/revision, firmware commit, motor models, buses, IDs, reply format, MIT mode, PMAX/VMAX/TMAX, torque/current scale, supply ratings and permitted logging build. Record these in META; `default_meta()` contains placeholders, not a robot configuration. The AGV firmware is useful reference material but is not proof of the borrowed WBR's configuration. Preserve the working firmware and controller gains.

Prepare the stand, guarded wheel area, restrained lever and calibrated scale, calipers, power isolation/e-stop, temperature monitoring, and optional scope/logic analyser. Test the e-stop and command-loss watchdog before excitation. Support the chassis mechanically, restrain legs, and keep people and cables outside every moving joint's swept volume. Energize one motor at a time for bench work. Never restrain a powered wheel by hand. Stop on unexpected motion, sign disagreement, saturation, stale feedback, bus errors, temperature/voltage limits or loss of logging. Torque zero alone is not power isolation.

## Ordered procedure and exit criteria

| Order / ID | Setup and acquisition | Recording duration | Exit criterion / interpretation |
|---|---|---|---|
| 1 / B0 | Motors disabled. Stream known counter-pattern records over the intended transport; verify CRC, sequence, drop counters, timestamp increments and simultaneous GPIO/SYNC capture. Exercise wrap in a test build or decoder fixture. | 60 s per transport/profile | No unexplained losses; sustained capacity exceeds selected profile with margin. FULL needs 209,374 bytes/s and does not fit UART 2 Mbaud. Benchmark USB CDC; its 800 kB/s budget is an assumption. |
| 2 / B1 | Stationary IMU module, raw counts and temperature, motors off. Record ranges, ODR, bandwidth, sample-stamp source and mounting. Keep still for startup (reference AGV uses 1 s warm-up + 3 s stable). Then record a stable-temperature segment. | 300 s initial; 3,600 s dedicated follow-up for low-frequency drift | Fit each gyro axis and each acceleration axis independently. Inspect Allan curves and gaps before fitting. The board-noise scenario needs 3,600 s for RRW within 25% at empirical p90; a 30-minute visit cannot satisfy that target. |
| 3 / R0 | On robot, torque disabled. Capture one known command and reply per motor. Compare decoded position, speed, torque and temperature with the vendor tool. | 30–60 s | Verify every mapping, scale and status nibble. Do not interpret an enable/disable/zero-position command as torque. Current is not automatically available in the existing CAN frame. |
| 4 / R1 | Torque disabled; move one joint at a time by hand and tip the chassis in each axis. Record a surveyed static pose and six stationary orientations for acceleration offset/scale checks. | 10 s per pose or motion; about 120 s total | Set motor signs/offsets, `R_BS`, CTRL signs, left mirroring and hip order. Check forward positive, leg length and leg angle against geometry. Verify physical send order: reference right task sends joint[1], joint[0], wheel. |
| 5 / E-M1 (R2) | Static, mechanically restrained lever on calibrated scale. With zero tare, sweep small torque levels up/down; repeat opposite torque sign when fixture permits. Log command, settled feedback, force, perpendicular lever length and temperature. | Synthetic minimum 18 s/motor; plan 30–60 s/motor plus cooldown | Fit shaft torque versus feedback torque (or settled command after verifying tracking), offset and sweep hysteresis. Recover `k`. Absolute Kt requires calibrated torque-producing current or a verified firmware Kt scale; DC-bus current is not a substitute. |
| 6 / E-M2 (R3a) | Wheel free and guarded. Run both speed directions and multiple magnitudes with bounded speed control. Rehearsal speeds are ±1,2,4,8,16,32 rad/s; reduce to the safe characterized range. Exclude acceleration/settling. | Synthetic minimum 9.6 s; plan 12 × (6.3 + 0.3) = 79.2 s/wheel, repeat warm | Fit Coulomb + viscous drive friction after applying measured `k`. At least a full revolution per plateau helps average cogging; verify actual steady speed. Plot residual versus speed, direction, angle and temperature. This does not measure tyre-ground friction. |
| 7 / E-M3 (R3b) | One free wheel, guarded. Small alternating torque steps with bounded speed and automatic cutoff; record actual quantized TX and RX. Rehearsal uses 0.15 N*m plus weak speed damping; begin lower on hardware. | Synthetic minimum 1 s; plan 10 s × 3 repeats per wheel | Fit delay and lag to torque feedback, then `k/J` to speed using separately calibrated friction. Repeat at native 3 ms cadence; use 1 ms only with an approved bench build and measured bus capacity. Sensor/feedback latency remains part of the effective delay. |
| 8 / R4 | Supported chassis, wheel clearance. Log CTRL sample identity, CAN_TX and raw IMU. Start with shadow controller output while motor power is disabled; if powered rocking is necessary, use the owner's safe stand mode. | 30 s timestamp recording; 10–30 s broad-band rocking | Method A gives sample-to-TX delay per axis, not shaft response or attitude-filter delay. Method B regresses torque on gyro/angle history; reject a flat cost curve or a fit at the delay-search boundary. Hand rocking is not guaranteed to reproduce the synthetic 0.5–8 Hz excitation. |
| 9 / R5 | Optional final balance response on the ground with overhead catch, clear area and the owner's already demonstrated controller. Use a small permitted reference step, with synchronized EVENT and external video/reference if available. | 10 s × 3 trials, with checks between trials | Only after R0–R4 and owner approval for this physical test. Save pitch, wheel speed, request/applied torque, saturation and timing. Compare held-out traces; do not tune Studio gains on this robot or claim dynamics validation without an independent reference. Skip if the prerequisites or time budget fail. |

The 0.3 s settling period is a synthetic setting, not evidence of physical settling. Extend it until measured acceleration is negligible. Repeat zero/tare checks after each thermal cycle. Do not operate at the simulated 30–42 V supply unless the actual board, motors and battery are rated for it.

## A realistic 30-minute robot slot

Do B0 and the dedicated long B1 run beforehand. Reserve 0–5 min for configuration/e-stop/stand checks, 5–9 min for R0/R1, 9–14 min for a 300 s stationary recording, 14–19 min for E-M1 on the two wheels, 19–23 min for friction plateaus, 23–26 min for steps, 26–28 min for R4, and 28–30 min for file verification and backup. This covers two wheels, not all six motors. R5 and the 3,600 s drift recording require another slot. Stop at the first failed prerequisite; shorten scope rather than safety checks.

## Files and analysis for every experiment

1. Save immutable raw binary/text plus META and an experiment note: operator, UTC start, firmware hash, serials, supply, mounting, ranges/filter settings, calibration instrument uncertainties, limits, temperature, mode and exclusions. Add `measurement_domain=hardware` only for actual measurements. Keep synthetic and measured records separate.
2. Emit `EVENT label=studio_t0` when starting the shared command profile; record starts/stops/mode changes and SYNC pulses. Restart the file after any MCU reboot or configuration change. Use the common 1 MHz timer; bounded log reordering is allowed, clock resets are not wraps.
3. Import with `python -m wbrlog capture.bin capture.csv --format long`. Inspect the receipt's CRC, malformed/truncation, sequence-gap, unmapped motor and unsupported-CAN counters. Any missing META or placeholders prevent physical interpretation. Keep gaps; never fill gaps with invented stationary noise for Allan fitting.
4. Compare shared channels using the EVENT and Studio grid (README example). ZOH answers what the controller could have seen; linear interpolation is for smooth state comparison. Check packet age separately: a held value is not proof of fresh data. Use angular interpolation/circular residuals for wrapped encoders.
5. Fit stationary gyro bias as a mean over a stated window; subtract known gravity projected into the sensor frame before interpreting an acceleration mean as bias. Use independent static poses to separate orientation error from acceleration bias. Fit Allan N/K only over supported slopes and enough clusters; repeat long recordings and thermal conditions before adopting drift parameters.
6. Store fit estimates, units, residuals, repeatability, exclusions, confidence limitations and source hashes in a new parameter candidate file. Retain nominal Studio files unchanged. Validate on a repeat not used in fitting. Acceptance here is preparation for measurement; actual robot dynamics remain unvalidated.
