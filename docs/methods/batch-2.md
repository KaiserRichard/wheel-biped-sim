# What batch 2 adds and what it does not show

## Tóm tắt tiếng Việt

**FROM FILE** · Đợt này đưa vào kho mã các thành phần độc lập để học và kiểm thử mô phỏng robot chân–bánh. Bộ điều khiển lưu ba lệnh cũ để mô hình hóa trễ. Bộ lọc kết hợp tín hiệu IMU và encoder, đồng thời theo dõi sai lệch gyro khi đủ điều kiện. Hai mô hình tổn hao tách mô-men cản bánh–sàn và mô-men bù trong bộ điều khiển. Khi mất lệnh từ máy chủ, sai số vị trí được neo lại ở thời điểm chuyển sang dừng.

## What this teaches

**FROM FILE / STANDARD PRACTICE** · The [S5 design](../../wbr/control/predictor/design.py) discretizes a six-state, two-effort plant with a zero-order hold. It designs LQR on `z[k] = [x[k], u[k-1], u[k-2], u[k-3]]`, with `x[k+1] = A_d x[k] + B_d u[k-3]`. The command queue makes the assumed delay part of the design. The script checks closed-loop poles after reducing the stored gain to float32. Separate sensor ages, transport jitter, saturation and interpolation between schedule nodes need separate checks.

**FROM FILE** · From the checkout root, run `python -m wbr.control.predictor.design <local-model.npz>`. The caller supplies continuous matrices `a` (6 × 6) and `b` (6 × 2), a scalar `tick_s`, and diagonal cost vectors `state_cost` (6 values) and `effort_cost` (2 values). The six states are forward position and speed, virtual-leg lean and rate, and body pitch and rate, all in SI. The signed result is used as `u = K z`. The [C template](../../wbr/control/predictor/s5_predictor.h) expects a caller-supplied `s5_gain_table.h` with ascending mass and length axes, two or more nodes per axis, gains indexed by effort, mass, length and coefficient, and three trim fields per mass/length pair, in this order, virtual-leg lean in radians, per-leg support in newtons, and per-leg sagittal effort in newton-metres. The [test table](../../tests/native/s5_gain_table.h) contains synthetic arithmetic values. Zero-initialize the command history. Store the current sagittal effort pair after computing feedback and clear the history when leaving the standing mode.

**FROM FILE / STANDARD PRACTICE** · The [S10 estimator](../../estimation/s10/s10_estimator.h) integrates bias-corrected gyro rates and uses gated gravity and wheel-odometry corrections. For pitch the prediction is `pitch += dt * (gyro_y - bias_y)`. The startup estimate uses stationary samples. Stationary and integral bias updates have different gates. Roll, pitch, acceleration, and gyro rate use body axes. The caller supplies aligned IMU sensor data, decoded wheel and leg kinematics, and ordered acquisition ticks in milliseconds. Use the acquisition timestamp for data age and the release timestamp for encoder consumption timing. The synthetic checks cover startup, packet order, drift correction, dropout, and the signed bias bound.

**FROM FILE / STANDARD PRACTICE** · The [rolling model](../../wbr/sim/rolling.py) applies `-Crr * Fz * r * tanh(omega_world / omega_s)` about each wheel's hinge axis in world coordinates. It uses world wheel spin, which includes rotation carried by the parent. The caller clears the owned torques, refreshes contact loads and velocities, and supplies one normal load per wheel. Because torque opposes world spin, its power contribution is nonpositive for a stationary floor. The [coast-down checks](../../tests/test_batch2_rolling.py) exercise both directions, two timesteps, and a no-loss control on an independent primitive fixture.

**FROM FILE** · The [S7 feedforward](../../wbr/control/wheel_loss/s7_wheel_loss.h) returns the torque request for two identical wheels in straight rolling. It adds twice the per-wheel viscous and smoothed rolling terms, using commanded wheel rate `v_ref / r`. Callers supply each physical input and apply their own actuator limits. The [S8 stop re-anchor](../../wbr/control/stop/s8_stop_position.h) zeros the stored position error on the first latched host-loss tick. Later ticks integrate `v_est - v_ref` within a caller-supplied bound. Releasing the latch clears the state for the next event.

**FROM FILE / STANDARD PRACTICE** · The [paired-trial rehearsal](../../wbr/sim/paired_trials.py) runs the same random push and packet-noise seed under two command-delay settings on the public primitive model. The controller receives noisy packets and the terminal dwell scorer uses plant samples. The report counts paired outcome flips and computes Wilson intervals per arm. Pairing limits changes in sample composition between arms. A temporary rest crossing can fail the terminal dwell if the robot moves again. Run from the checkout root with `python -m wbr.sim.paired_trials --seed 42 --count 8`.

**FROM FILE** · To run the released Python and native C checks from the checkout root, use `python -B -m pytest -q -p no:cacheprovider tests` with GCC on the path or `CC` set to a C11 compiler with compatible flags. Pytest writes C executables to its scratch directory.

## What the real robot must confirm

**UNKNOWN / STANDARD PRACTICE** · Measure installed plant parameters and the discrete feedback path, including acquisition age, transport, torque limits, and the effect of interpolation on stability. Use independently measured attitude and speed to check gyro warm-up, acceleration bias, encoder signs, slip, and estimator gate behavior. Use separate unloaded wheel spin-down and loaded coast-down tests to distinguish drive damping from floor-dependent rolling loss.

**UNKNOWN / STANDARD PRACTICE** · Verify the host-loss latch, position reset, limiting, and sustained stop in a supported low-speed bench trial. The synthetic cases give these checks a starting point. Full-plant CAD campaign results, official mission acceptance, target processor timing, and physical robot performance remain outside the evidence supplied here.
